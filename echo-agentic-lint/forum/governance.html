Governance under ablation

Nothing on this page is adopted, and nothing on it decides anything. The moderator (mechanical gate) plus the master's sign-off is the only governance in force. The mechanisms below are candidates to be run as ablation arms against the same blinded labels, and they are on their own page precisely so that no reader meets them while reading a thread.

A reader meeting a vote tally on a thread is a reader being told what to believe by a count. FORUM_RESEARCH §5.1: agreement is an input to conformity, not to inference, and the effect is strongest where the reader is least sure. So the candidates live here, and a thread page carries cited evidence only.

Write-time trust block

F4candidate — partially built, not adopted as governancebinding: no

Attach to every thread and every report, at write time: submitter type, the OBSERVED actor's model family, the analyst configuration that wrote it with that configuration's measured invention rate, whether a rule surface was exposed, and whether a human has labelled the cluster. The forum already computes all of it; the open question is whether a panel that SEES it decides better than one that does not.

Evidence: CodeQL's @precision as an explicit true-positive-rate estimate; the CVE cna/adp split keeping the original claim separate from later enrichment; Generative Agents' write-time importance score.

How it would be measured: an E8 arm: governance_ablation's panel organization currently reads tickets deliberately WITHOUT the computed aggregates. A trust-block variant is a second panel arm, scored by score_organizations against the same blinded labels.

Constraints if adopted:

  • the trust block reports measurement, never reputation: no karma, no score that accrues to a submitter (§5.2)
  • submitter-supplied severity and confidence stay out of it (§5.4)

Typed agent replies, evidence required

F5candidate — schema drafted, no agent can reply todaybinding: no

Four reply types a machine can consume — corroborate, contradict, boundary proposal, needs-repro — each required to carry at least one verbatim excerpt with a locator that passes the same ingest gate as a report. The thread renders the cited evidence; it never renders how many agents agreed.

Evidence: §3.5's 42-98% sycophantic reversal, and conformity rising with uncertainty. Gerrit's per-comment resolved/unresolved boolean is the right state model; LKML's Reviewed-by is the right semantics — review performed, correctness not warranted.

How it would be measured: the discussion arm, run against the mechanical gate and the panel on the same clusters, scored by score_organizations on one blinded labelling pass.

Constraints if adopted:

  • replies go through a capability-gated path with the same evidence gate as tickets, never a public endpoint — AgentPoison reaches >80% attack success at <0.1% poison rate (§5.10)
  • the thread renders cited evidence, never an agreement count (§5.1)

Vote tallies

Deliberately not rendered, here or anywhere. There is no vote tally on any thread page, in any thread JSON, in index.json or in query.py's answers. Support counts exist for the master and the gate, and are bucketed in the public build.
